# SG Family Wealth — Command Centre

Private family-office dashboard. Every figure is derived from the reconciled holdings
book; nothing on screen is estimated or placeholder.

> **Private repository.** It contains the full portfolio (₹324 Cr, 862 positions with
> folio numbers) and advisor minutes marked *Confidential — Not for circulation*.
> Do not make it public, fork it to a public org, or add collaborators casually.

## Stack

TanStack Start · React 19 · Vite 7 · Tailwind v4 · Recharts · Supabase (mirror only)

## Getting started

```bash
bun install          # or: npm install
bun run dev          # http://localhost:5199
bun run build
```

Behind a TLS-inspecting corporate proxy, point Node at the proxy's root CA:

```bash
export NODE_EXTRA_CA_CERTS=/path/to/corp-ca.pem
```

## Where the data comes from

The app reads **bundled JSON snapshots**, not a live database, so it always renders a
self-consistent book:

| Snapshot | Generated by | Source |
|---|---|---|
| `src/data/holdings-snapshot.json` | `scripts/import_excel.py` | `excel/SG Family Portfolio Holdings*.xlsx` |
| `src/data/transactions-snapshot.json` | `scripts/import_excel.py` | `excel/Transaction File*.xlsx` |
| `src/data/meetings-snapshot.json` | `scripts/import_minutes.py` | `Minutes for meetings with advisors/*.pdf,*.docx` |

```bash
python -m pip install openpyxl pypdf python-docx
python scripts/import_excel.py     # holdings + transactions, reconciles to R1_Summary
python scripts/import_minutes.py   # advisor minutes, actions, per-advisor grouping
```

`import_excel.py` reconciles every section against the workbook's own `R1_Summary`
control total and prints the variances. Some are expected — `R6_Summary_Bullion`
contains `#REF!` errors, so R1 understates bullion. Lot-level detail wins; the
difference is reported rather than plugged.

## Daily refresh

`scripts/daily_sync.ps1` re-imports the workbook and mirrors it to Supabase. Register
it once:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\daily_sync.ps1 -Install
```

Full detail in [`scripts/README_SYNC.md`](scripts/README_SYNC.md).

## Supabase

Supabase is a **mirror**, not the source. The app never reads from it at runtime —
`getSnapshotComparison()` only reports how far the database has drifted from the
workbook. Writes need a service-role key; the anon key is blocked by row-level
security.

`scripts/out/meetings.sql` creates tables for advisor meetings if you want those
shared across devices rather than living in browser localStorage.

## What lives in the browser, not in git

Three things are authored in the app and stored in `localStorage`. They are **not**
in this repo and **not** in the daily backup:

- **Cell corrections** to the holdings grid (`sg-holding-overrides`) — keyed on a
  natural key, so they survive re-import
- **Advisor meetings and actions you write yourself** (`sg-meetings`)
- **Status tracking on actions extracted from minutes** (`sg-minutes-tracking`)

Use **Backup** on the Advisor Meetings page to export them as JSON.


## Known data issues

Surfaced in the app on **Data Source & Health**, and worth fixing at source:

- **NSE Unlisted Shares carries ₹0 cost** against ₹16.20 Cr of value — inflates the
  Equity class to +96.6% and the book to +38.22%
- **`advisor_name` is empty** for all rows, so Custodian Review falls back to broker
- **No sector column**, so equity risk cannot be broken down by sector
- **`SG` / `SG Family` / `SGQ` / `SGO`** are deliberately *not* merged — they are
  separate legal entities with their own folio numbers
